# Journal Editor

Googleログイン後、Journalを端末内に保存し、Firestoreへ同期するMarkdownエディタです。

公開URL: https://orangemark0808-code.github.io/mytool/journal-editor/

## 2026-10-16の改善

### v2026-10-16-6：記事一覧を2列カードへ変更

- 通常一覧は画面幅900px以上で2列、狭いiPadやスマホでは1列にします。タイトル・タグ・本文抜粋を上側、作成日・更新日とピン止め・ごみ箱操作を下側にまとめました。
- 日記タグは濃いオレンジの背景と白文字にして、選択中の記事の淡い背景から区別します。
- 作成日順・更新日順とピン止め優先は維持し、左から右、上から下の順に表示します。ごみ箱はチェック・復元しやすい従来の1列表示を維持します。記事の保存内容は変更しません。

### v2026-10-16-5：PC・iPad・スマホの操作と記事一覧を改善

- 通常の記事一覧は「作成日が新しい順」「更新日が新しい順」を選べます。ピン止め記事はどちらも先頭に置き、ピン同士はピン止めした順、同じ日時はID順に固定します。選択はブラウザごとに記憶します。検索・カテゴリでの絞り込みと組み合わせられ、ごみ箱は更新日の新しい順を維持します。並び替えで記事や日時は変更しません。
- ごみ箱の戻る矢印に「記事一覧へ」の文字を付けました。ヘッダーからも通常一覧へ戻れます。
- 一覧ではタイトル末尾の「競合コピー」「復元」を重複しないラベルへ分け、タイトル・抜粋・日時の強弱を調整しました。表示だけの変更で、保存済みのタイトルや本文は書き換えません。編集欄・Markdown出力・バックアップには保存されたタイトルを使用します。
- スマホ、およびiPadなどのタッチ端末では、本文にフォーカスしている間だけタイトル・カテゴリ・表示切替を畳み、本文を広く表示します。「完了」でキーボードを閉じると操作欄が戻ります。入力中も既存の端末保存・変換中の保護を続けます。
- PCでは編集操作を常時表示します。タッチ対応PCでもマウス操作を検出した場合は通常の編集レイアウトに戻します。画面幅700px以下では画面スペースを優先してコンパクト表示を使います。
- タッチ端末の編集バーは画面下端に置き、VisualViewportの高さに合わせて本文の表示領域を調整します。ブラウザ上の画面幅確認は行いますが、実機のソフトウェアキーボードや変換の挙動は別途確認が必要です。

### v2026-10-16-3：端末ごとの記事一覧の不一致と復元コピーの増殖を修正

- 一覧の取得結果に記事がないだけでは削除と判定しません。サーバー限定の個別読み取りで存在を確認し、保存完了より遅れた一覧通知でも復元コピーを自動生成しません。
- 過去に端末内の「削除済み」記録へ入った記事がサーバーに存在する場合も、個別確認後にその記録を解除して再表示します。実際に完全削除されている記事は戻しません。
- 保存済みで未編集の記事が別端末で削除された場合は、その削除を反映します。開いていた場合は一覧へ戻ります。未送信の編集・日本語変換中の入力は保持し、送信時の競合処理で保護します。
- 「クラウド同期済み」はローカルの記事ID・内容・版が確認済みサーバーデータと一致し、個別確認がすべて終わっている場合に限ります。確認に失敗した場合はローカルデータを保持して同期エラーを表示します。
- 既存の競合コピーや復元コピーは自動削除・統合・改名しません。今後の競合コピーでは、タイトル末尾の自動付記を重ねず一つにします。
- 診断情報に記事数・確認状態・SHA-256の比較用ハッシュを追加しました。接続先とアカウントの組み合わせ、ローカルとクラウドの記事を比較できます。本文・タイトル・メールアドレス・生のユーザーID・接続先設定はコピーしません。

### v2026-10-16-2：同期と入力の修正

- 保存の完了待ち中に別ブラウザから削除・更新が届き、保存結果と受信内容が一致しない場合は、保存処理が落ち着いてからサーバーへ再接続して確認します。古い受信内容を再適用して本文を戻すことはせず、確認中は「同期済み」にしません。
- 記事とカテゴリそれぞれの直近のサーバー確認状態を同期表示に反映します。キャッシュ由来の通知へ戻ったときは「同期を確認中」に切り替えます。ブラウザの復帰・ページ復元・再接続・手動再試行では購読を再開し、削除や更新を取り直します。
- 本文とタイトルの日本語変換中も端末内には保存します。変換中の新しい送信、受信内容による入力欄の書き換え、先に送信した保存結果の適用は、変換終了まで保留します。変換確定後に最終入力を保存し、競合時は既存の競合コピーで双方を保護します。
- プレビューを見た後の新規作成でも、入力モードで開きます。
- 診断コピーに記事・カテゴリのサーバー確認状態を追加しました。本文・タイトル・アカウント情報は含めません。
- 自動テストは通信の順序と入力イベントを模擬します。iPad実機のキーボード・日本語変換・回線切替は別途確認が必要です。

- Journal一覧の各記事にピン止めボタン（ごみ箱アイコンの左）を追加しました。ピン止めした記事は絞り込み・検索の結果の中で先頭に表示し、複数ある場合は新しくピン止めした順に並べます。押下中のボタンはオレンジで塗り、行の左端にも印を付けます。
- ピン止めは記事の`pinnedAt`として端末内とFirestoreに保存し、別端末にも同期します。本文・タイトル・カテゴリ・作成日・更新日は変更しません。ごみ箱ではピン止めを表示せず更新日順のままです。復元するとピン止めも戻ります。
- 旧バージョンを開いたままのタブで記事を編集すると、その記事のピン止めは外れることがあります。

## 2026-10-09の改善

- Journal一覧のカテゴリ・投稿状況タグを押すと、その記事のタグを変更できます。選択後に自動保存し、本文・タイトル・作成日は保持します。検索・絞り込みにも即時反映します。ごみ箱内のタグは表示だけです。
- ごみ箱ではチェックした記事だけを完全削除できます。「表示中をすべて選択」も使え、検索条件を変えると選択を解除します。対象タイトルと件数を確認してから削除し、復元・変更された記事は削除せず、通信・権限エラー時も元データを保持します。
- 完全削除はクラウドの対象記事と端末内の保存レコードを除去します。別端末のごみ箱データは、サーバーの削除を確認した同期で除去し、遅れて届く削除済みデータの再表示・再送を防ぎます。JSONバックアップや別に作ったコピーは削除対象外です。自動削除・保存期限は設けていません。
- ごみ箱の件数バッジは、濃いオレンジ系の塗りつぶしに白い数字で表示します。
- 一覧上部のごみ箱・新規作成もSVGアイコンで表示します。新規作成はヘッダーと同じ書類＋、ごみ箱は1件以上で件数バッジを表示し、ごみ箱内では一覧に戻る矢印へ切り替えます。操作名・件数は読み上げとツールチップにも残します。
- Journal一覧は作成日の新しい順で表示します。編集・カテゴリ変更で更新日が変わっても並び順は変わりません。同じ作成日時はIDで順序を固定し、ごみ箱は従来の更新日順を維持します。
- Journal一覧では日記をオレンジ系、note用を緑系、未投稿を青系、投稿済をグレー系のタグで区別します。投稿状況の表示名は「投稿済」に統一し、保存する値は従来のままです。
- 一覧は「すべて／日記／note用」で絞り込みできます。note用では「すべて／未投稿／投稿済」も選べ、検索と組み合わせられます。別カテゴリへ切り替えると投稿状況の絞り込みを解除します。
- 記事タイトルを押すと入力モードで編集画面を開きます。独立した編集ボタンは削除し、各記事の操作欄はごみ箱アイコンだけにしています。タイトルとごみ箱には44pxの操作領域を確保します。
- 一覧に並び順を明示し、カテゴリ・投稿状況タグの高さ・文字サイズ・余白を統一しています。
- 本文・補足・日時・ラベル・入力案内は濃い茶色（#2C2016）に統一。見出しは従来の#3A2A1Aを維持します。
- Journal Editorの本文はユーザー指定の例外として、入力欄・プレビューともに `"Nunito", "Yu Gothic UI", "Meiryo", sans-serif` を使用します。和文の字間の見え方を従来に戻すための指定です。見出し・操作UIはオレンジマニアUIの書体、コードはDM Monoを維持します。本文の文字サイズ16px・字間normal・文字色#2C2016は変更しません。指定フォントのない端末では端末標準のsans-serifを使用します。
- スマホの編集バーを画面下端へ固定。キーボード表示時はVisualViewportに追従します。
- 改行・段落・取り消し・やり直し・太字を常時表示し、その他の操作を展開できます。
- カテゴリはタイトル付近へ移動しました。
- 新規記事のカテゴリは日記です。選択肢は日記、note用、追加したカテゴリ、未分類の順に表示します。既存記事の分類は自動で変えません。
- 設定の「未分類を日記へ変更」から、ごみ箱を除く未分類の記事をまとめて変更できます。変更時点の分類と日記カテゴリをサーバーで確認し、本文・タイトル・投稿状況を書き直さず、カテゴリ情報と更新情報だけを変更します。
- note用の記事では投稿状況（未投稿／投稿済）を選べます。未設定の初期値は未投稿です。投稿状況も端末内とFirestoreに保存し、一覧表示・検索・バックアップ・ごみ箱の復元に引き継ぎます。
- 日本語変換中のEnterには干渉せず、リスト中のEnterは項目を続けます。
- 箇条書き・引用・見出しは選択した行へ適用します。
- コピーと.md保存はどちらもタイトルを含む同じMarkdownを出力します。
- Markdownプレビューは見出し、強調、リンク、リスト、引用、コード、区切り線に対応します。完全なCommonMark互換やnoteの表示再現を保証するものではありません。

## 保存・同期

端末内の下書きとカテゴリはGoogleアカウント別に管理します。入力直後に端末へ保存し、約400ms後に送信します。オフラインの編集は未同期として残し、再接続・再起動時に送信します。

記事の送信はFirestoreトランザクションで基準の版を確認します。別端末の変更と競合した場合は、元の記事を上書きせず「競合コピー」を作成します。送信中の追加入力も未同期として残します。キャッシュ由来の空一覧は削除判定に使いません。

削除は`deletedAt`を設定するごみ箱方式です。本文を保持したまま、ごみ箱から復元できます。物理削除はサーバーへの個別読み取りで確認して反映します。保存済みで未編集の記事を自動復元することはありません。未送信の編集がある場合は送信トランザクションで復元用下書きへ退避し、文章を保持します。

カテゴリの名称・ID・順序・削除状態は、既存のアカウント専用メタデータ領域`users/{uid}/blogEditorMigrations/editorCategoriesV2`へ保存します。`firestore.rules.proposed`の既存matchがこのドキュメントを含みます。実運用ルールは別途確認が必要ですが、この修正で権限を広げることはありません。

旧形式のlocalStorageは削除しません。サーバーからのJournal・カテゴリの取得を確認して照合し、クラウドに同じ内容がある場合は再取り込みの案内を出しません。旧カテゴリのIDがPCとスマホで異なっても、クラウドに同じ名前のカテゴリが一つだけある場合はそのIDへ対応付けます。

この端末だけの記事や内容の異なる記事が残る場合は、件数とタイトルを設定で確認し、差分だけを明示操作で取り込めます。異なる内容の同じIDがある場合は別の下書きとして残します。設定の「この端末の旧データを確認」には取り込み元の記事数・カテゴリ数・タイトルを表示します。「取り込まず案内を閉じる」はこのブラウザだけに作用し、旧データを保持します。「差分を再確認」で再表示できます。キャッシュやオフラインの未確認データだけでは取り込み済みと判定しません。

設定から全Journal（ごみ箱を含む）とカテゴリのJSONバックアップを保存できます。診断コピーには本文・タイトル・メールアドレス・ユーザーIDを含めません。

## 開発時の確認

新しいパッケージのインストールは不要です。Node.js 20以上で実行できます。

```powershell
node --test journal-editor/tests/core.test.mjs journal-editor/tests/integration.test.mjs journal-editor/tests/publish.test.mjs
node journal-editor/tests/preview-server.mjs
```

ブラウザで`http://localhost:8765/`を開きます。この確認サーバーは架空の長文を表示し、Firebase設定・認証情報・実際のJournalを読み込みません。公開用成果物には確認サーバーやテストを含めません。

`?scenario=legacy-matched`でクラウドと同じ旧データ、`?scenario=legacy-difference`で内容の異なる旧データの案内、`?scenario=badges`でタグ・作成日順・ピン止め、`?scenario=trash`で完全削除の確認画面を検証できます。trashの削除はメモリ上のモックに限定され、Firebaseには接続しません。旧形式のlocalStorageは書き換えず、確認画面内だけで架空のデータを使用します。

実際のログインを試す場合は、元の案内どおりHTTPサーバー経由で起動してください。`index.html`の直接起動（file://）は対応していません。

```powershell
cd C:\Users\antig\mytool\journal-editor
python -m http.server 8080
```

実機で確認する項目: iPhone Safari・Android Chromeのキーボード開閉、変換確定Enter、長文末尾のカーソル、画面回転、同じ記事の端末間競合、オフライン編集と再接続。ローカルの幅変更だけでは実機キーボードの挙動までは確認できません。
