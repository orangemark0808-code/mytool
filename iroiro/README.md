# イロイロキロク

## 食材のチェックリスト

- 題名・カテゴリー（フォームではタグ表記）が「食材」のカード1枚を開き、その中に複数の食材を登録します。食材ごとのカードは作りません。空になってもカードは残ります。
- 共通の「＋」から空の新規メモを作り、カテゴリーを「食材」に切り替えた場合も、題名を持つ既存の食材カードを開きます。空の食材カードは未保存と表示し、そのまま一覧に戻れます。入力済みの本文・項目がある新規メモは置き換えません。
- 題名の「食材」の自動入力は新規作成で「食材」を選んだ場合だけです。他のカテゴリーには入力しません。入力済みの題名や既存メモの題名をカテゴリー変更時に上書きしません。
- 入力の検証で保存を止めた場合は「未保存（入力内容を確認）」と表示し、「保存中…」のままにしません。題名を修正して保存できた場合は以前の題名エラーも解除します。
- 1項目は1回分の食材です。「豚こま150g」を2項目として追加でき、同じ名前・量でも別々のIDで保持します。「同じ内容で2件追加」も使えます。
- 量は数値または分数（例：150、1、1/2）を入力し、単位はg・個・本・玉・枚・束・袋・パックから選択します。「その他」で単位を自由入力できます。分数は表示を保ち、野菜をgへ自動換算しません。
- 食材ごとに保存場所、早めに使いたい、消費期限／賞味期限、日付、メモを保持します。新しい項目は食材名・正の量・単位を確認してから追加し、入力途中のフォームを閉じる操作では未確定の入力を保持します。
- 使った項目にチェックを入れて「チェックした食材を削除」で取り除きます。「削除を元に戻す」で直前の削除を取り消せます。使用量の差し引き操作はありません。チェックした項目は献立候補の対象から外せます。
- `foodList.items`に各項目の`id,name,quantity,unit,storage,useSoon,expiryKind,expiryDate,memo,checked,order`を保存します。`quantity`は分数を保持する文字列です。
- `food-inventory-{categoryId}`という固定IDのメモに保存するため、別端末で同時に初回作成してもカードは増えません。項目の追記はID単位で統合し、同じ項目の異なる編集や削除との競合は入力を保持して保存を止めます。
- 旧1食材1メモは元データを残して一覧へ引き継ぎます。初めて編集を確定したときに一覧を保存し、`foodList.importedSources`に取込済みIDを保持するため、項目を削除しても元データから復活しません。取り込み前の元データが別端末で変わった場合は保存を止めます。
- 一覧と取込済みIDはバックアップ・復元にも含めます。旧形式の`food`フィールドの読み込みも維持します。
- 「今日のお知らせ」との献立連携は今後の工程です。連携ではチェックされていない各項目を1回分として扱い、肉のg数と野菜の登録単位を保ちます。

カード型メモアプリです。公開時の想定URLは `https://orangemark0808-code.github.io/mytool/iroiro/` です。

一覧のカード右下の星から、詳細画面を開かずにピン留め・解除できます。未設定は☆、設定済みは★です。保存中は連打を防ぎ、失敗時は元の表示へ戻します。ピン留めの変更で本文・タスク状態・更新日は書き換えません。

## タスク管理

- カテゴリー名が「タスク」のとき、専用フォームに切り替わります。タスク一覧から新規作成すると、そのカテゴリーを引き継ぎます。
- タスク名、任意の期限、状態（未着手・進行中・完了）、優先度（高・通常・低）、チェック項目、補足メモを自動保存します。内容のあるタスクはタスク名が必要です。空の新規タスクは保存しません。
- タスク一覧は期限の近い順で表示し、完了したタスクを折り畳みます。カードのチェックボックスから完了・未着手を切り替えられます。
- 期限は端末の現地日付で判定します。未完了で期限を過ぎたタスクを強調し、日付が変わると表示を更新します。
- タスク設定は `task` フィールド、補足メモは既存の `content` フィールドに保存します。カテゴリーを切り替えてもタスク設定と元の入力形式を保持します。既存の箇条書き・チェックリストは、タスクとして保存するまで元データを書き換えません。

## 漫画のネタ管理

- カテゴリー名が「漫画」のとき、ネタキロクと同じ項目を持つ専用フォームを表示します。漫画一覧からの新規作成は、そのカテゴリーを引き継ぎます。
- タイトル、制作状況、ジャンル、タグ、自分用メモを入力し、ページごとにコマID・人物名や状況・区分・詳細・参照や補足を記録できます。ページ数はページ追加に合わせて自動更新します。
- コマは追加・複製・上下への移動・削除ができます。内容は通常のメモと同じ保存待ち処理でFirestoreへ自動保存します。内容がある場合は漫画タイトルが必要です。
- CSVコピー・ダウンロードは、ネタキロクと同じ7列（タイトル、ページ番号、コマID、人物名、区分、詳細、参照・補足）です。表計算ソフトで数式となる文字列には先頭にアポストロフィを付けます。
- 漫画の設定とページは `manga` フィールド、自分用メモは既存の `content` フィールドに保存します。カテゴリーを切り替えても既存の文章・項目・タスク設定を保持し、バックアップにも漫画の全項目を含めます。
- カテゴリー管理の「ネタキロクの記録を取り込む」から、同じアカウントの保存済み記録を漫画カテゴリーへコピーできます。旧形式のコマ行も読み込み、制作状況・ジャンル・タグ・メモ・ページ・コマ・作成日・更新日を引き継ぎます。
- 取り込み元IDから保存先IDを固定し、トランザクションで既存データを確認するため、再実行しても重複せず、取り込み後の編集を上書きしません。元のネタキロクの記録は変更・削除しません。取り込み後に保存内容を読み直して照合します。オンライン接続が必要です。

## バックアップと移行

- 復元時は既存メモを残し、同じIDのメモをバックアップ内容で更新します。
- カテゴリーは最新のFirestore設定とID単位で統合します。既存カテゴリーを残し、同じIDはバックアップ内容で更新します。
- 復元するメモ・カテゴリーのIDは英数字、`_`、`-` の1〜1500文字に限定します。カテゴリーIDの `all`、予約形式の `__...__`、重複IDは使えません。
- 関連リンクは保存済みのURLキャッシュを使用せず、本文からHTTP/HTTPSのURLを再生成します。
- ローカルメモの移行では保存先IDを固定し、移行済みのメモを上書きしません。途中で失敗した場合は再試行できます。
- カテゴリー統合と移行にはFirestoreのトランザクションを使うため、オンライン接続が必要です。

## 今日のお知らせからのタスク追加（2026-10-25-01）

今日のお知らせの入力操作に限り、同じFirebase認証を使うdashboard-sync画面からタスクを追加する。認証情報はGitHub Pages内に保持し、今日のお知らせには渡さない。Firestoreルール・承認済みドメインの変更は不要。

カテゴリー名を前後空白除去して「タスク」に一致するIDを取得する。題名を前後空白除去して同じチェックリスト（既存のtask.items形式を含む）へ追記し、重複題名はupdatedAtの新しいメモを選ぶ。なければ既存スキーマのチェックリストメモを新規作成する。状態・優先度・期限はメモ単位のtask設定であり、既存メモの設定は変更しない。新規はtodo / normal / 期限なし、項目はchecked:false。

追加はトランザクションで最新の項目を読み、既存項目をそのまま末尾へ追記する。操作IDを既存の項目idとして使い、結果不明時の同じ操作の再試行を重複させない。同時に同名グループを新規作成する競合も防ぐため、既存iroiroSettings/mainのupdatedAtだけを同じトランザクションで更新する。カテゴリーの内容は変更せず、新しいフィールド・コレクション・スキーマ番号も追加しない。

編集画面の既存メモ保存もトランザクションを使う。開いた時点・手元の変更・サーバーの最新値を比較し、別の項目への追記や変更を統合する。同じ項目の同じフィールドを別々に変更した場合や、削除と編集が競合した場合は入力を保持して保存を停止し、黙って上書きしない。削除済みメモを再作成しない。更新後は、ほかの端末で開きっぱなしの旧画面も一度読み込み直してから使用する。

テスト：`node --test iroiro/tests/*.test.mjs`。保存形式・旧チェックリスト・最新同名メモの選択・二重送信・同時新規作成・編集中の追記・競合時の入力保持を検証する。

### 2026-10-25-02：追加時の誤った競合判定を修正

Firestoreの通常取得とトランザクション取得では、同じ内容でもMapのフィールド順が異なる場合がある。設定の一致判定をJSON文字列から、Mapはキー順を無視・配列は順番を維持・Timestampは精度を維持する値比較に変更した。本当に設定や更新時刻が変わった場合の競合保護は維持する。
